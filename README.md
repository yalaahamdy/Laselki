# WaveTalk — لاسلكي Wi-Fi للمجموعات

<div dir="rtl">

**WaveTalk** تطبيق أندرويد يحوّل هاتفك إلى **جهاز لاسلكي (Walkie-Talkie) رقمي حقيقي** يعمل داخل شبكة Wi-Fi المحلية: اكتشاف تلقائي للأجهزة، اختيار قناة، ضغط الزر للتحدث، ووصول الصوت فورياً للأجهزة الأخرى — **بدون إنترنت، بدون حسابات، بدون خوادم سحابية**.

```
        الراوتر / نقطة الاتصال
                │
           Wi-Fi محلي
        ┌───────┼───────┐
     هاتف A   هاتف B   هاتف C
     (WaveTalk على نفس القناة = يسمعون بعضهم)
```

---

## الفكرة في سطر واحد

> اكتشاف الأجهزة تلقائياً عبر UDP → اختيار القناة/الجهاز → **الضغط باستمرار على الزر** → بث الصوت المشفر مباشرة عبر الشبكة المحلية → رفع الإصبع يوقف الإرسال.

## أهم المميزات

| الميزة | التفاصيل |
|---|---|
| اكتشاف تلقائي | إعلانات UDP دورية + أحداث فورية، تعرّف على الأجهزة خلال ~ثانية |
| قنوات اتصال | انضم/أنشئ قناة بأي اسم (Team, Family…) — الأجهزة على نفس القناة فقط تسمع بعضها |
| Push-to-Talk | زر دائري كبير بحالات بصرية (خامل/إرسال/مشغول/خطأ) + مؤشر مستوى صوت حي |
| نصف مزدوج | شخص واحد يتحدث في اللحظة؛ المحاولات المتزامنة تُرفض برسالة "القناة مشغولة" |
| ترميز صوتي | IMA ADPCM بمعامل ضغط 4:1، إطارات 20ms، جودة كلام ممتازة على الشبكة المحلية |
| تشفير | AES-128-CTR بمفتاح جلسة مشتق من سر القناة + Nonces لكل اتصال |
| مقاومة الأخطاء | Jitter Buffer متكيّف، إعادة اكتشاف عند تغيّر الشبكة، Heartbeat و Timeout، صفر توقف عند انقطاع Wi-Fi |
| خصوصية | لا حسابات، لا تحليلات، لا إنترنت، لا تخزين صوت — Local-First بالكامل |
| واجهة عربية/إنجليزية | RTL كامل + وضع داكن/فاتح متناسق |

## المتطلبات

- **هاتفان أو أكثر بنظام Android 8.0 (API 26) أو أحدث**.
- اتصال الجميع بنفس شبكة Wi-Fi (أو نفس نقطة Hotspot).
- للبناء: Android Studio (Ladybug أو أحدث) أو JDK 17 + Android SDK 35.

> ملاحظة: لا يلزم وجود إنترنت في الراوتر — شبكة محلية معزولة تكفي تماماً. يعمل التطبيق أيضاً عبر Hotspot الخاص بالهاتف.

## التثبيت السريع (ملف APK)

1. انقل `WiFiWalkieTalkie.apk` إلى الهاتفين.
2. اسمح بـ"التثبيت من مصادر غير معروفة" عند الطلب.
3. ثبّت وافتح التطبيق على الجهازين.
4. اتبع شاشة الترحيب (اسم الجهاز + صلاحية الميكروفون).
5. تأكد أن الجهازين على **نفس القناة** (افتراضياً `Lobby`).

## ربط هاتفين خطوة بخطوة

1. وصّل الهاتفين بنفس شبكة Wi-Fi.
2. افتح WaveTalk على الجهازين — سيظهر كل جهاز الآخر تلقائياً في قائمة "الأجهزة".
3. (اختياري) اضغط على شريحة القناة أعلى الشاشة لإنشاء قناة مثل `Team`، وكرر على الجهاز الآخر.
4. اضغط باستمرار على الزر الدائري الكبير على الجهاز A وتحدث — سترى "جارٍ الإرسال" وشريط الموجة يتحرك.
5. الجهاز B سيرى اسم المتحدث وسماع الصوت فوراً عبر مكبر الصوت.
6. ارفع إصبعك يتوقف الإرسال فوراً — ثم اضغط من الجهاز B للرد.

**للتحدث مع جهاز بعينه:** اضغط على اسم الجهاز في القائمة — سيقتصر الإرسال عليه وحده (يظهر "التحدث مع: …" أعلى القائمة).

## البناء من الكود المصدري

### عبر Android Studio
1. افتح مجلد المشروع (سيُزامن Gradle تلقائياً).
2. `Build ▸ Generate Signed App Bundle/APK` أو شغّل مباشرة على جهاز.

### عبر سطر الأوامر

```bash
# نسخة Debug
./gradlew assembleDebug

# نسخة Release موقعة (ملف keystore.properties و keystore/ مرفقان)
./gradlew assembleRelease
# الناتج: app/build/outputs/apk/release/app-release.apk
```

**مفاتيح التوقيع المرفقة** (لإعادة بناء حزمة مطابقة — مناسبة لأن هذا تطبيق محلي؛ غيّرها إن رغبت بالنشر):

```
keystore/wavetalk-release.keystore
storePassword: wavetalk2025 | keyAlias: wavetalk | keyPassword: wavetalk2025
```

### تشغيل الاختبارات

```bash
./gradlew testDebugUnitTest
```

تشمل 43 اختباراً: ترميز ADPCM (جودة/أحجام/حدود)، بروتوكول الإطارات والمصافحة، تشفير الجلسات، متتبع الحضور، Jitter Buffer، **اختباري تكامل حقيقيان** يبنيان خادم/عميل TCP فعليين على loopback ويبثان صوتاً مشفراً ويتحققان من سلامته، واختبار اكتشاف UDP حقيقي بين عقدتين.

## البنية التقنية

```
app/src/main/java/com/wavetalk/app/
├── core/         ثوابت البروتوكول + سجل الأحداث
├── domain/       نماذج (Device, TalkScope, EngineState…)
├── discovery/    بروتوكول UDP الثنائي + PresenceTracker + DiscoveryService
├── network/      فحص الواجهات وحساب عناوين البث + مراقب Wi-Fi
├── audio/        AdpcmCodec + AudioCapturer + AudioPlayer + JitterBuffer + ToneFeedback
├── transport/    WireProtocol (إطارات/مصافحة) + SessionCrypto (AES-CTR) + TCP Server/Link
├── session/      TalkEngine: التنسيق الكامل، نصف المزدوج، إدارة الاتصال
├── settings/     DataStore (الاسم، القناة، المظهر، الكسب…)
└── presentation/ Compose UI: Onboarding + Walkie + Settings + Theme + Icons
```

**مسار الصوت:** `AudioRecord (16kHz/mono/20ms) → كسب → ADPCM → [seq|ADPCM] → AES-CTR → TCP (Nagle off) → فك التشفير → Jitter Buffer → ADPCM decode → AudioTrack (سماعة).`

**مسار الاكتشاف:** إعلان UDP كل 1.2s (Magic + نسخة + UUID + اسم + قناة + منفذ + حالة التحدث) إلى عنوان بث الشبكة الفرعية + 255.255.255.255، وأحداث TALK_START/STOP فورية. انعدام الإعلانات 4 ثوانٍ = Offline، و10 ثوانٍ = إزالة.

## الصلاحيات ولماذا

| الصلاحية | السبب |
|---|---|
| `RECORD_AUDIO` | التقاط الصوت **فقط أثناء الضغط على زر التحدث** — لا تسجيل خلفي إطلاقاً |
| `INTERNET` / `ACCESS_NETWORK_STATE` / `ACCESS_WIFI_STATE` | فتح Sockets على الشبكة المحلية ومعرفة حالة الاتصال (لا يُرسل أي شيء للإنترنت) |
| `CHANGE_WIFI_MULTICAST_STATE` | استقبال حزم الاكتشاف Broadcast/Multicast على Wi-Fi |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE` | إبقاء الاكتشاف حياً في الخلفية (Android 14 يتطلب تصريح النوع) |
| `POST_NOTIFICATIONS` | إشعار "جاهز" الصامت الدائم (اختياري، Android 13+) |
| `VIBRATE` / `WAKE_LOCK` | اهتزاز عند الضغط + منع نوم المعالج أثناء الإرسال |

**لا يوجد:** موقع، تخزين، جهات اتصال، هوية، تحليلات، إعلانات.

## قيود معروفة

- **AP/Client Isolation**: بعض الراوترات تعزل الأجهزة عن بعضها (شائع في الشبكات العامة/الضيوف) — عندها لن يرى الجهازان بعضهما. الحل: عطّل "AP Isolation" من إعدادات الراوتر أو استخدم Hotspot.
- **التشفير** يحمي من التنصت السلبي على الشبكة؛ المستخدم الذي يعرف اسم القناة يستطيع الانضمام أصلاً — إن أردت خصوصية أعلى استخدم اسم قناة غير متوقع (خطة مستقبلية: PIN للقناة).
- بعض واجهات الشركات المخصصة (Xiaomi/Huawei…) تقتل الخدمات الخلفية بقوة — فعّل "عدم التحسين" للتطبيق من إعدادات البطارية إن لزم.
- استخدام مكبر الصوت مع الميكروفون قد يسبب صدى خفيفاً في بعض الأجهزة — ميكروفون `VOICE_COMMUNICATION` يفعّل إلغاء الصدى النظامي، ولأفضل جودة استخدم سماعة.
- النسخة الأولى تجربة صوتية 16kHz mono محسّنة للكلام (وليست الموسيقى).

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| لا تظهر أي أجهزة | تأكد من نفس الشبكة والقناة، وجرّب إعادة فتح التطبيق على الجهازين |
| "القناة مشغولة" دائماً | شخص آخر يبث فعلاً أو حالة متبقية — تُصحح تلقائياً خلال ثوانٍ |
| الصوت متقطع | قرّب الجهازين من الراوتر؛ Jitter Buffer يتكيف تلقائياً بعد لحظات |
| اختفاء الجهاز بعد قفل الشاشة | فعّل "البقاء جاهزاً في الخلفية" واستثنِ التطبيق من تحسين البطارية |

## English TL;DR

**WaveTalk** is a real Wi-Fi Walkie-Talkie for Android (8.0+): automatic UDP device discovery on the local network, named channels, hold-to-talk Push-to-Talk with 20ms IMA-ADPCM audio streamed over AES-128-CTR-encrypted TCP. No internet, no accounts, no servers, no tracking — fully local-first. Build: `./gradlew assembleRelease` (keystore included). Test: `./gradlew testDebugUnitTest` (43 tests incl. real loopback TCP audio + UDP discovery integration). Known limitation: routers with AP Isolation block peer discovery.
